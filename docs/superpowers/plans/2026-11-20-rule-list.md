# Plan: proxy rule list (PAC) instead of an all-traffic proxy

## Why
While the downloader ran, every app's web traffic went through it (system HTTP/HTTPS proxy, or the
VPN helper's State entry). Stopping it cut every open connection, and apps that save the proxy at
launch (the Claude app) kept using the dead proxy until restarted (seen 2026-11-19 15:35 and
2026-11-20 11:55 in ~/Library/Logs/Claude/main.log).

## Evidence before building (2026-11-20)
- WeChatAppEx (Chromium) contains ProxyAutoConfigEnable / ProxyAutoConfigURLString.
- VM rehearsal: PAC on → *.qq.com / *.qpic.cn → PROXY 127.0.0.1:2023; others DIRECT; PAC unreachable
  → all DIRECT; undo clean; no password needed for networksetup.
- Live on the user's Mac (VPN off): PAC set 12:27:04, WeChat started 12:29:05, WeChatAppEx opened 3
  connections to 2023. Download button not testable without the VPN on that network; tested later with the VPN on.

## Design
1. RuleList.swift (DownloaderCore)
   - ruleListPort 2024, ruleListURL http://127.0.0.1:2024/proxy.pac, WeChat domains qq.com, qpic.cn, wechat.com.
   - ruleListScript(downloaderUp:) — "PROXY 127.0.0.1:2023; DIRECT" for WeChat domains; everything
     DIRECT when the downloader isn't listening.
   - turnOnRuleList(runner:) / turnOffRuleList(runner:) via networksetup -get/-setautoproxyurl/-setautoproxystate.
     Never overwrite an enabled rule list that isn't ours; off only touches ours.
   - appConfigYAML(from:) — copy of config.yaml with proxy.system false; app runs the downloader with
     -c app-config.yaml. config.yaml and the Terminal launcher stay unchanged.
2. RuleListServer (DownloaderCore): NWListener bound to 127.0.0.1:2024, answers every request with the
   script (application/x-ns-proxy-autoconfig). Started at app launch and before every Start.
3. Controller: Start → write app-config, launch with -c, turn on rule list. cleanProxy also turns the
   rule list off (same "nothing listening on 2023" guard). Port 2024 busy → Start fails with a message.
4. isDownloaderEffectiveProxy also accepts ProxyAutoConfigEnable 1 + our URL (routed / leftover).
5. VPN helper v4: apply() writes ProxyAutoConfigEnable/URLString (+ marker) instead of HTTP/HTTPS
   proxy. App shows "Update helper" (one password).

## Known limits
- Terminal launcher keeps the old all-traffic proxy (unchanged file); with helper v4 in VPN mode it
  needs the app open (rule list server), otherwise WeChat goes direct.
- A service with someone else's rule list enabled is left alone, so WeChat isn't routed on it.

## Tests (TDD, RED first)
- ruleListScript routing evaluated with macOS's own PAC engine (CFNetworkCopyProxiesForAutoConfigurationScript).
- server serves the script over HTTP on a test port; down → DIRECT.
- turnOn/turnOff calls with FakeRunner, foreign PAC kept.
- appConfigYAML flips only proxy.system.
- controller: start passes -c app-config.yaml and turns the rule list on; stop turns it off.
- effective-proxy parser accepts PAC; helper v4 writes PAC keys (fake scutil).
